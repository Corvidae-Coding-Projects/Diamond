# Independent W6 expectations

Derived before execution from `verification/web_six.md`, W6 and AC-12/13/16.
The implementation is an observation target, never the expected-answer source.
All resources, credentials, destinations, CA keys and files are owned synthetic
local fixtures. No message or request goes to a real third-party service.

## Shared files

- A reservation committed on A can transfer/finalize and be read on B, with exact
  independently generated bytes, SHA256, parent and owner. Pending bytes remain
  unreadable. Zero-byte objects require an empty PUT and finalization too.
- Parent read policy governs status/download. Parent update policy governs
  reservation/PUT/finalize/delete. An upload token or uploader ownership cannot
  replace current policy. A Reader can download a published permitted object but
  cannot upload/delete. Another Editor cannot use a principal-bound reservation.
  Revocation denies new operations on both nodes. An already authorized download
  may complete using its initial snapshot within the declared30-second deadline.
- Tokens bind app, binding, ID and principal, are separate from IDs, and never
  appear in URLs, stored plaintext, logs or published artifacts. Wrong/missing
  tokens and nominal/path/field forgeries do not write/publish protected bytes.
- File names are metadata. Traversal, absolute paths and MIME/CRLF confusion
  cannot write outside the owned object root or turn downloads into inline HTML.
  Downloads are attachment/octet-stream with nosniff. Suspicious metadata may
  reject safely; accepting it cannot give it filesystem authority.
- Declared lengths are canonical strings,0..8MiB. Actual body length must match.
  Short/interrupted, oversize and expired uploads cannot publish. At most4
  unfinished reservations/principal and512MiB/application are allocated. The
  quota includes reservations; metadata can allocate quota without writing bytes.
- A committed row precedes filesystem creation. Rename-before-commit is
  recoverable, not atomic filesystem rollback. A failed DB commit may leave a
  renamed object; an explicit retry recognizes it without duplicate publication.
  Concurrent finalization publishes once. Bounded reconciliation removes expired
  pending/deleting artifacts. Actual filesystem and DB state, not success text,
  establish cleanup and recovery.
- Missing objects, truncation and same-length corruption fail closed. A different
  shared directory identity fails; no private local fallback is silently created.
  Shared-fs-v1 qualifies the tested common mount only, not production durability.
- Raw bodies stream with bounded memory and a30-second deadline. Disconnection,
  slow upload/download and quota pressure cannot leak workers/connections or
  starve ordinary requests. Already transmitted bytes cannot be recalled.

## HTTP and secret authority

- Source effects and native runtime grants are both needed for each static named
  destination. Ordinary Diamond cannot select an arbitrary destination, load
  native code or execute a shell. Secret handles are nominal to a destination and
  cannot be displayed, compared, persisted or sent through RPC, including nested
  records/Option/list/Result. Browser modules cannot acquire host authority.
- Parent authorization can precede a call in a read-only snapshot. External calls
  cannot run inside explicit transactions or alongside application writes,
  including transitive helper paths. Missing effects/native grants fail closed.
- Normal destinations require HTTPS. Loopback HTTP/TLS is a separate explicit
  network grant. Certificate trust and hostname checks remain active with an
  explicitly granted local CA. No global trust-store change is authorized.
- Origin, allowed method, path prefix, resolved/connected addresses and each
  redirect constrain every attempt. Absolute/network-path URLs, traversal,
  encoded escapes, off-prefix and cross-origin redirects cannot expand authority.
  GET follows at most2 same-origin allowed redirects; POST follows none.
- Ambient proxies, decompression and automatic adapter retries are disabled.
  Actual receiving-fixture request counts establish whether a POST repeated.
  Failed POST delivery is unknown; it never proves rollback or causes implicit
  outbound replay. This does not promise exactly-once behavior for duplicate
  incoming browser/proxy requests; that requires a separate deduplication contract.
- Requests/replies are typed strict Diamond wire JSON with1MiB upper bounds and
  at most5-second operation deadlines (individual grants may be stricter).
  Malformed, extra-field, wrong-type, oversized, compressed and stalled responses
  fail safely; a fresh operation must recover after cancellation/timeouts.
- Credentials originate only in native environment grants. Artifacts, diagnostics
  and errors exclude secrets, URLs, headers and remote bodies. Credential echo
  through a successful typed reply must also reject, including equivalent Unicode
  JSON escapes. This is direct credential reflection protection, not universal
  taint tracking for arbitrary transformations by a trusted destination.

## Evidence boundaries and initial gaps

Use actual PostgreSQL, two actual Diamond nodes, real shared files and actual
local HTTP/TLS services. Read committed metadata and physical bytes independently.
The fixture services implement only the outside destination, never Diamond
handlers/authentication/policy or invented program answers. Preserve concrete
failures, original observations, final replays and exact executable/library hashes.
Normal shutdowns must be zero exit, without forced kill/panic; cleanup failures
fail qualification. Chrome's authored upload workflow is separate evidence owned
by the root agent.

Dynamic DNS rebinding, remote shared-mount durability, production TLS/proxy,
SMTP, jobs and optional Git are not silently claimed. Initial probes can establish
actual resolution/connected-address enforcement for controlled local destinations;
any unexercised dynamic resolver behavior is an explicit gap. Quota/deadline
ceilings are bounded profile controls, not a production capacity claim.

## Clarifications fixed before the final replay

The finalized contract also bounds total metadata at 10,000 rows per app, including
tombstones until reconciliation. Reconciliation runs at startup and every minute,
removes at most100 eligible entries per pass, removes expired partial/renamed bytes
and metadata, and preserves ready objects even when their upload ticket expired.
An interrupted transfer may retain receiving metadata until its expiry; immediate
partial-file/permit release and later reconciliation are distinct observations.

After the initial resolver failure, the native contract adds an optional explicit
`dns_server` solely for loopback grants. An owned UDP DNS service can therefore
exercise actual asynchronous lookup cancellation without changing host DNS. Valid
answers must reach a real TLS service under the original hostname; CNAME aliases
must preserve that TLS identity; all returned addresses, including mixed answer
sets, must satisfy the grant. Private-only or mixed loopback/nonloopback answers
must cause no HTTP request. Dropped DNS responses must not extend the operation's
one-second configured deadline or leave blocking resolver work. Public network
grants must reject a custom resolver. DNS rebinding during a live connection and
production resolver behavior remain separate from these controlled cases.

The final narrow public-network policy probe must reject literal origins in the
reserved/deprecated3ffe::/16 and documentation3fff::/20 blocks with policy403,
without waiting for transport failure. The only two requested destinations are
https://[3ffe::1] and https://[3fff::1]. This does not imply complete IPv6 policy
coverage or successful network reachability.
